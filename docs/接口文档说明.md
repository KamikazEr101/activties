## 全局说明

### 统一响应格式

所有接口均返回以下JSON格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

- `code`: 状态码（200表示成功，其他表示错误）
- `message`: 响应消息
- `data`: 响应数据（可能为null）

### 认证机制

大部分接口需要JWT认证，请在请求头中携带：

```
Authorization: Bearer {token}
```

**认证失败错误码**:
- `401`: 未授权（缺少Token）
- `4006`: 令牌无效
- `4007`: 令牌已过期

### 错误码体系

- **200-299**: 成功响应
- **400-499**: 客户端错误
- **500-599**: 服务端错误
- **1000-1999**: 活动模块业务错误
- **2000-2999**: 报名模块业务错误
- **3000-3999**: 签到模块业务错误
- **4000-4999**: 用户认证模块业务错误

### 2.2 更新活动

**接口功能**:  
更新活动信息。根据活动当前状态，时间字段的修改受到不同限制。

**请求URL**:

**认证要求**:  
✅ 需要JWT认证

**权限要求**:  
只有创建者或超级管理员可以修改

**请求参数**:

*请求头*:
- `Authorization`: Bearer {token} (JWT令牌，必填)
- `Content-Type`: application/json

```json
  "id": 1,

  "activityType": "ACADEMIC",

  "registrationEndTime": "2025-12-19T23:59:59",
  "startTime": "2025-12-20T14:00:00",
  "endTime": "2025-12-20T17:00:00",
  "location": "学术报告厅A201",
  "organizer": "计算机学院",
  "contactPerson": "王老师",
  "contactPhone": "13812345678",
  "maxParticipants": 200,
  "posterUrl": "https://example.com/poster_new.jpg"
}
```

**字段校验规则**:
- `id`: 必填
- 其他字段校验同创建接口
- **时间字段为可选输入**：如果不传递某个时间字段，系统会使用原活动的对应时间值

**时间字段修改规则**:

根据活动当前状态，时间字段的修改受到不同限制：

1. **未发布(0)**: 所有时间字段可自由修改

2. **报名中(1)**:
   - **报名开始前**（当前时间 < registrationStartTime）:
     - `registrationStartTime` 可修改，但必须在当前时间之后
     - 其他时间字段可修改
   - **报名进行中**（registrationStartTime <= 当前时间 < registrationEndTime）:
     - `registrationStartTime` **不可修改**
     - `registrationEndTime` 可修改，但必须在当前时间之后
     - `startTime` 和 `endTime` 可修改

3. **报名结束(2)**（报名截止但活动未开始）:
   - `registrationStartTime` 和 `registrationEndTime` **不可修改**
   - `startTime` 可修改，但必须在当前时间之后
   - `endTime` 可修改

4. **进行中(3)**:
   - `registrationStartTime` 和 `registrationEndTime` **不可修改**
   - `startTime` **不可修改**
   - `endTime` 可修改，但必须在当前时间之后（可延长活动）

5. **已结束(4)**: 所有时间字段**不可修改**

6. **已取消(5)**: 不允许修改

**响应格式**:

*成功响应 (HTTP 200)*:
返回更新后的完整活动详情，格式同创建接口

*错误响应示例*:

活动不存在 (HTTP 400):
```json
{
  "code": 1001,
  "message": "活动不存在或已删除",
  "data": null
}
```

权限不足 (HTTP 400):
```json
{
  "code": 4005,
  "message": "权限不足，无法访问",
  "data": null
}
```

时间修改限制 (HTTP 400):
```json
{
  "code": 1007,
  "message": "报名开始时间不能修改",
  "data": null
}
```

**可能的错误码**:
| 错误码 | HTTP状态 | 含义               |
| ------ | -------- | ------------------ |
| 200    | 200      | 更新成功           |
| 400    | 400      | 参数校验失败       |
| 401    | 401      | 未授权             |
| 1001   | 400      | 活动不存在或已删除 |
| 1007   | 400      | 活动时间设置不合理 |
| 4001   | 400      | 请先登录           |
| 4005   | 400      | 权限不足           |
| 4006   | 401      | 令牌无效           |
| 4007   | 401      | 令牌已过期         |
| 500    | 500      | 系统内部错误       |

**特殊说明**:
- 更新后自动清除活动详情和列表的Redis缓存
- 时间字段的修改限制基于活动当前状态和当前时间
- 时间字段为可选参数，未传递的字段将保持原值
- 所有时间修改必须满足基本逻辑：报名开始 < 报名结束 <= 活动开始 < 活动结束
- 只有创建者或超级管理员（roleType=2）可修改

## H5扫码签到流程说明

### 完整流程:

1. **管理员生成二维码**:
   - 调用`GET /registration/{activityId}/qrcode`接口
   - 获得包含checkInToken的二维码图片和签到链接
   - 二维码链接格式:`http://localhost:8080/h5/checkin?token=xxx`
   - Token有效期30分钟

2. **学生扫描二维码**:
   - 扫描后浏览器打开H5页面
   - 从URL参数中获取token

3. **前端验证Token**:
   - 调用`GET /h5/checkin/validate?token=xxx`
   - 验证Token是否有效
   - 如果有效,显示签到表单;如果无效,提示二维码已失效

4. **学生输入手机号**:
   - 在表单中输入报名时使用的手机号
   - 点击"立即签到"按钮

5. **提交签到请求**:
   - 调用`POST /h5/checkin`接口
   - 提交checkInToken和studentPhone
   - 系统验证并完成签到

6. **显示签到结果**:
   - 签到成功:显示成功提示和签到时间
   - 签到失败:显示错误信息(未报名、已签到、活动未开始等)

### 前端页面建议:

```html
<!-- H5签到页面结构示例 -->
<div class="checkin-page">
  <header>高校学生活动管理系统</header>
  
  <div class="checkin-form">
    <h2>活动签到</h2>
    <input type="tel" placeholder="请输入报名手机号" />
    <button>立即签到</button>
  </div>
  
  <div class="result-message">
    <!-- 显示签到结果 -->
  </div>
</div>
```

### 错误处理建议:

- Token过期:提示"二维码已失效,请联系工作人员刷新"
- 未报名:提示"您未报名此活动,无法签到"
- 已签到:提示"您已完成签到,签到时间:xxx"
- 活动未开始:提示"活动尚未开始,请在活动开始后签到"
- 活动已结束:提示"活动已结束,签到时间已过"

## 文件上传最佳实践

### 文件命名规范:

- **活动封面**:`activity_cover_{activityId}_{timestamp}`
- **活动海报**:`activity_poster_{activityId}_{timestamp}`
- **通用文件**:`general_{timestamp}_{random}`

### 前端上传示例:

```javascript
// 普通文件上传
const formData = new FormData();
formData.append('file', fileInput.files[0]);
formData.append('purpose', 'activity_cover');

fetch('/file/upload', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + token
  },
  body: formData
})
.then(response => response.json())
.then(data => {
  console.log('文件上传成功:', data.data.url);
});

// Base64上传(Canvas导出)
canvas.toDataURL('image/jpeg', 0.9)
  .then(base64Data => {
    return fetch('/file/upload/base64?fileName=canvas.jpg&purpose=activity_cover', {
      method: 'POST',
      headers: {
        'Authorization': 'Bearer ' + token,
        'Content-Type': 'text/plain'
      },
      body: base64Data
    });
  })
  .then(response => response.json())
  .then(data => {
    console.log('Base64上传成功:', data.data.url);
  });
```

### 安全建议:

1. **文件类型检查**:前端和后端都应验证文件类型
2. **文件大小限制**:限制单文件最大50MB,防止存储空间滥用
3. **病毒扫描**:生产环境建议集成病毒扫描服务
4. **访问控制**:MinIO桶设置为公开只读,只有后端服务可上传/删除
5. **CDN加速**:对于公开访问的文件,建议配置CDN加速访问

### 存储说明:

- 使用MinIO对象存储服务
- 文件按用途(purpose)分目录存储
- MinIO桶策略设置为公开只读访问
- 后端服务使用管理员凭证进行上传/删除操作
- 文件URL永久有效,适合活动海报等公开内容
- 支持HTTPS加密传输
